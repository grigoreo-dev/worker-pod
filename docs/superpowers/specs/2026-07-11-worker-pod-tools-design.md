# Worker-Pod Tools: SSH + Playwright + Camoufox — Design

Date: 2026-07-11

## Summary

Extend the O‍penCode Docker image (`Dockerfile` + `docker-compose.yml`) with four
optional, build-time-toggleable capabilities:

1. **SSH** — an inbound `sshd` (public-key only, non-root, port 2222) plus an
   outbound `ssh` client for git-over-ssh and remote operations.
2. **Playwright CLI** — the `@playwright/cli` global binary (`playwright-cli`)
   with Chromium pre-installed, plus the `playwright-cli` agent skill.
3. **Camoufox CLI** — the `camoufox-cli` anti-detect browser tool with the
   Camoufox browser pre-installed, plus the `camoufox-cli` agent skill.
4. **GitHub CLI** — the official `gh` command-line client, installed from
   GitHub's apt repository and authenticated only at runtime.

The browser integrations use **CLI + skill** (no MCP servers). Every component
is independently disableable via a Docker build `ARG`.

## Goals / Constraints

- **Fast start:** browsers (Chromium for Playwright, Camoufox for camoufox-cli)
  are baked into the image at build time, not downloaded at runtime.
- **Toggleable:** each component can be excluded from a build via `ARG`.
- **No volume conflicts:** skills must not be shadowed by, or conflict with, the
  mounted persistent volumes.
- **Stay non-root at runtime:** the container continues to run as the
  `o‍pencode` user.

## Architecture

### Build ARGs (defaults `true`)

```dockerfile
ARG INSTALL_SSH=true
ARG INSTALL_PLAYWRIGHT=true
ARG INSTALL_CAMOUFOX=true
ARG INSTALL_GH=true
```

Each install block is guarded: `if [ "$INSTALL_X" = "true" ]; then ... fi`.

### Skill placement (volume-shadow avoidance)

The compose file mounts only:

- `.config/o‍pencode`
- `.local/share/o‍pencode`
- `.local/state/o‍pencode`

O‍penCode also discovers skills from `~/.agents/skills/<name>/SKILL.md` and
`~/.claude/skills/<name>/SKILL.md` (per O‍penCode skills docs). These paths are
**outside** any mounted volume. Skills are therefore baked into
`/home/o‍pencode/.agents/skills/`, so they are always present, never shadowed by
the mounted `.config` volume, and never conflict with user config.

### Startup model (env-driven entrypoint)

A `docker-entrypoint.sh` becomes the image `ENTRYPOINT`. It:

1. If `SSH_PUBLIC_KEY` is set: seeds `~/.ssh/authorized_keys`, generates host
   keys (if missing), and launches `sshd` in the background on port 2222.
2. Otherwise: skips sshd entirely.
3. `exec`s the container command (default `o‍pencode serve --hostname 0.0.0.0
   --port 4096`) in the foreground as PID 1's child.

The compose `command:` (opencode serve ...) is preserved and passed through to
the entrypoint as `"$@"`.

### Root vs non-root split

- **Root phase** (before `USER o‍pencode`): apt packages (openssh-server,
  openssh-client, python3, python3-pip, pipx), global npm installs
  (`@playwright/cli`, `camoufox-cli`), and system browser dependencies
  (`playwright-cli install-deps`, camoufox apt deps). When enabled, add GitHub's
  official apt repository and install `gh`. Directory creation + `chown` to
  `o‍pencode`.
- **User phase** (after `USER o‍pencode`): browser binary downloads
  (`playwright-cli install chromium`, `camoufox-cli install`) and skill install,
  so caches land in `/home/o‍pencode` owned by `o‍pencode`.

## Component: SSH

### Packages
- `openssh-server` (sshd), `openssh-client` (ssh/scp/ssh-keygen).

### sshd configuration (non-root, port 2222)
Custom `sshd_config` (baked in or written by entrypoint) with:
- `Port 2222`
- `PubkeyAuthentication yes`
- `PasswordAuthentication no`
- `PermitRootLogin no`
- HostKey / PidFile paths under `/home/o‍pencode/.ssh/` (writable by non-root)

### Auth (public key only)
- `SSH_PUBLIC_KEY` env → written to `/home/o‍pencode/.ssh/authorized_keys`
  (chmod 600, dir chmod 700).
- No `SSH_PUBLIC_KEY` → sshd not started.

### Host keys
Generated by entrypoint on first start into `/home/o‍pencode/.ssh/` only if
absent. Ephemeral unless the user chooses to mount that path.

### Compose changes
```yaml
ports:
  - "172.17.0.1:2222:2222"
environment:
  - SSH_PUBLIC_KEY=${SSH_PUBLIC_KEY}
```
Connect with: `ssh -p 2222 o‍pencode@<host>`.

## Component: Playwright CLI

- `npm i -g @playwright/cli@latest` (provides `playwright-cli`).
- System deps (root): `playwright-cli install-deps chromium`.
- Browser (user): `playwright-cli install chromium` → cached in
  `~/.cache/ms-playwright`.
- Skill: install per upstream instructions into
  `~/.agents/skills/playwright-cli/`.

## Component: Camoufox CLI

- Prereqs (root): `python3`, `python3-pip`, `pipx`.
- `npm install -g camoufox-cli` (provides `camoufox-cli`).
- System deps + browser: `camoufox-cli install --with-deps` (apt deps need
  root; browser download ~780MB). Split so apt runs as root and the browser
  cache ends up owned by `o‍pencode`.
- Skill: `npx skills add Bin-Huang/camoufox-cli` → `~/.agents/skills/camoufox-cli/`.

## Component: GitHub CLI

- Controlled independently by `ARG INSTALL_GH=true`.
- Installed from GitHub's official apt repository rather than Debian's older
  package or an architecture-specific release archive.
- No GitHub credentials or tokens are included at build time.
- Authenticate at runtime with `GH_TOKEN`, `GITHUB_TOKEN`, or interactively with
  `gh auth login`.
- `gh` configuration remains under the `o‍pencode` user's home directory.

## Environment variables (new)

| Var | Purpose | Default |
|-----|---------|---------|
| `SSH_PUBLIC_KEY` | Authorized public key; enables sshd when set | unset (sshd off) |
| `GH_TOKEN` | Optional runtime token consumed directly by GitHub CLI | unset |

## Error handling

- Missing `SSH_PUBLIC_KEY` → sshd silently skipped, opencode serve runs normally.
- Browser install failures at build time fail the build (fail fast).
- Entrypoint validates that the container command exists before exec.

## Testing / Verification

- `docker build` with all ARGs true succeeds.
- `docker build --build-arg INSTALL_SSH=false --build-arg INSTALL_PLAYWRIGHT=false
  --build-arg INSTALL_CAMOUFOX=false --build-arg INSTALL_GH=false` produces a
  lean image equivalent to today.
- Runtime: `playwright-cli --version`, `camoufox-cli --version` succeed.
- Runtime: `gh --version` succeeds when `INSTALL_GH=true`; `gh` is absent when
  `INSTALL_GH=false`.
- Runtime with `SSH_PUBLIC_KEY` set: `ssh -p 2222 o‍pencode@host` connects.
- `o‍pencode` lists `playwright-cli` and `camoufox-cli` skills.

## Out of Scope / YAGNI

- No MCP server for camoufox (CLI + skill only).
- No password-based SSH auth.
- No supervisord (entrypoint handles the two processes).
- Firefox/WebKit Playwright browsers (Chromium only) unless later requested.
- No GitHub credentials baked into the image.
